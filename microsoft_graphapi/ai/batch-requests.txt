BATCH REQUESTS
==============

Module: GraphApi.Batch
Limit: Up to 20 requests per HTTP call via POST /$batch


HOW IT WORKS
------------

Every resource function has a _query variant that returns a %Batch.Request{}
instead of executing immediately. Collect these into a Batch and execute
them all in a single HTTP call.


BATCH.REQUEST STRUCT
--------------------

    %GraphApi.Batch.Request{
      method: String.t(),        # "GET", "POST", "PATCH", "DELETE", "PUT"
      url: String.t(),           # e.g., "/users"
      body: map() | binary() | nil,
      headers: map() | nil,
      query: OData.t() | map() | nil,
      as: module() | nil,        # schema/view for casting
      depends_on: [String.t()] | nil
    }


FUNCTIONS
---------

  GraphApi.Batch.new()
  @spec new() :: Batch.t()
  Creates a new empty batch.

  GraphApi.Batch.add(batch, id, request, add_opts \\ [])
  @spec add(Batch.t(), String.t(), Batch.Request.t(), keyword()) :: Batch.t()
  Adds a request to the batch with the given string ID.
  Options:
    :depends_on - List of request IDs that must complete first.

  GraphApi.Batch.execute(batch, opts \\ [])
  @spec execute(Batch.t(), keyword()) :: {:ok, [map()]} | {:error, term()}
  Executes the batch via POST /$batch.
  Options: :client, :access_token, :api_version
  Returns {:ok, [response]} where each response has :id, :status, :headers, :body.
  Response bodies are auto-cast using the :as schema from each request.
  Returns {:error, "Batch limited to 20 requests, got N"} if over 20.

  GraphApi.Batch.get(responses, id)
  @spec get([map()], String.t()) :: map() | nil
  Finds a response by its request ID.


BUILDING _QUERY VARIANTS
-------------------------

Every resource function has a _query counterpart:

    Function                    _query variant
    --------                    --------------
    Users.list(opts)            Users.list_query(opts)
    Users.get(id, opts)         Users.get_query(id, opts)
    Users.create(attrs, opts)   Users.create_query(attrs, opts)
    Users.update(id, a, opts)   Users.update_query(id, a, opts)
    Users.delete(id, opts)      Users.delete_query(id, opts)
    Groups.list_members(id, o)  Groups.list_members_query(id, o)
    ... and so on for all resource functions

The _query variant accepts the same arguments but returns a
%Batch.Request{} instead of executing the HTTP call.

Pass :query and :as options to _query variants:

    Users.list_query(query: odata_query, as: GraphApi.Schema.User)


BASIC EXAMPLE
-------------

    alias GraphApi.{Batch, OData, Users, Groups}
    alias GraphApi.Schema.{User, Group}

    query = OData.new() |> OData.select(["id", "displayName"]) |> OData.top(5)

    {:ok, responses} =
      Batch.new()
      |> Batch.add("1", Users.list_query(query: query, as: User))
      |> Batch.add("2", Groups.get_query("group-id", as: Group))
      |> Batch.add("3", Users.create_query(%{"displayName" => "New"}, as: User))
      |> Batch.execute(client: client)

    # Access individual responses
    %{status: 200, body: %{"value" => users}} = Batch.get(responses, "1")
    # users => [%User{id: "...", display_name: "Alice"}, ...]

    %{status: 200, body: group} = Batch.get(responses, "2")
    # group => %Group{id: "...", display_name: "Engineering"}


SEQUENTIAL DEPENDENCIES
------------------------

Use depends_on to control execution order within a batch:

    Batch.new()
    |> Batch.add("1", Users.create_query(%{"displayName" => "New User"}, as: User))
    |> Batch.add("2", Groups.add_member_query("group-id", "new-user-id"), depends_on: ["1"])
    |> Batch.execute(client: client)

The depends_on option adds a "dependsOn" array to the serialized request,
telling Microsoft Graph to execute request "2" only after "1" completes.


RESPONSE FORMAT
---------------

Each response in the list is a map:

    %{
      id: "1",           # String ID matching the request
      status: 200,       # HTTP status code
      headers: %{...},   # Response headers
      body: ...          # Response body (auto-cast if :as was specified)
    }

Responses are sorted by ID.

If :as was provided on the request AND the response status is 2xx,
the body is automatically cast through the schema's from_map/1.
For collection responses (with "value" key), each item is cast.


URL BUILDING
------------

When a Batch.Request has a :query (OData struct or map), the parameters
are serialized into the URL as query string parameters:

    # Request with OData query
    Users.list_query(query: OData.new() |> OData.select(["id"]) |> OData.top(5))
    # Serialized URL: /users?%24select=id&%24top=5


LIMITS
------

- Maximum 20 requests per batch
- Batch.execute returns an error if you exceed this limit
- Empty batches return {:ok, []}
