MIDDLEWARE
=========

Modules: GraphApi.Middleware.Auth, GraphApi.Middleware.ErrorHandling,
         GraphApi.Middleware.Retry

The library uses Req request/response steps as middleware. All three are
automatically attached when you create a client via GraphApi.Client.new().


MIDDLEWARE STACK
----------------

Attached in this order by GraphApi.Client.new():

  1. Auth           (request step - prepended)
  2. ErrorHandling  (response step - appended)
  3. Retry          (response step - appended)

Request flow:
  Your call -> Auth adds token -> HTTP request -> Retry handles 429 ->
  ErrorHandling parses errors -> Response returned to you


GRAPHAPI.MIDDLEWARE.AUTH
------------------------

Module: GraphApi.Middleware.Auth

Req request step that injects the Authorization: Bearer <token> header.

  GraphApi.Middleware.Auth.attach(request)
  @spec attach(Req.Request.t()) :: Req.Request.t()
  Prepends the auth step to a Req request.

Token resolution order:
  1. Per-request :access_token option (delegated permissions)
     - If present and non-empty string, uses it directly
  2. TokenStore using client credentials config
     - If :microsoft_graph_config is set on the request options
     - Calls TokenStore.get_token(config, token_store)
  3. If neither is available:
     - Returns a 401 response with error message
     - "No access_token or client credentials config provided"

Registered request options:
  :microsoft_graph_config      - %GraphApi.Config{} struct
  :microsoft_graph_token_store - GenServer name/pid (default: GraphApi.TokenStore)
  :access_token                - Per-request OAuth token string


GRAPHAPI.MIDDLEWARE.ERRORHANDLING
----------------------------------

Module: GraphApi.Middleware.ErrorHandling

Req response step that parses non-2xx responses into structured error types.

  GraphApi.Middleware.ErrorHandling.attach(request)
  @spec attach(Req.Request.t()) :: Req.Request.t()
  Appends the error handling step to a Req request.

Behavior:
  - 200-299: passes through unchanged
  - 429: creates %RateLimitError{} with retry_after from Retry-After header
  - Other 4xx/5xx: creates %ApiError{} with status, code, message, details

Error extraction:
  The middleware looks for {"error": {"code": "...", "message": "..."}}
  in the response body (standard Graph API error format).

The error struct is placed in response.body as {:error, struct},
which is then unwrapped by GraphApi.Response.normalize/1.


GRAPHAPI.MIDDLEWARE.RETRY
--------------------------

Module: GraphApi.Middleware.Retry

Req response step that handles retries for 429 (Too Many Requests).

  GraphApi.Middleware.Retry.attach(request)
  @spec attach(Req.Request.t()) :: Req.Request.t()
  Appends the retry step to a Req request.

Configuration:
  Max retries:          3
  Default retry delay:  1,000 ms (1 second)

Behavior:
  1. On 429 response, checks retry count (stored in request options)
  2. If retries < 3:
     a. Reads Retry-After header for wait time (in seconds)
     b. If no header, uses exponential backoff: 1s, 2s, 4s
     c. Sleeps for the computed delay
     d. Increments retry count and re-executes the request
  3. If retries >= 3:
     a. Returns the 429 response (ErrorHandling then wraps as RateLimitError)

Registered request options:
  :microsoft_graph_retry_count - Internal counter (do not set manually)

Retry-After parsing:
  - Reads first value from "retry-after" response header
  - Parses as integer (seconds)
  - Multiplies by 1000 for milliseconds
  - Falls back to exponential backoff on parse failure

Exponential backoff formula:
  delay_ms = 1000 * 2^retry_count
  Retry 0: 1000ms
  Retry 1: 2000ms
  Retry 2: 4000ms


BYPASSING MIDDLEWARE IN TESTS
------------------------------

When you pass a custom client via the :client option, the middleware
is only present if you explicitly attach it. Using Req.new(plug: ...)
creates a client WITHOUT the Graph API middleware, which is ideal for
testing:

    # No middleware - direct stub responses
    client = Req.new(plug: {Req.Test, :my_stub})
    GraphApi.Users.list(client: client)

If you need to test WITH middleware, create a client via
GraphApi.Client.new() but with a test plug attached:

    client = GraphApi.Client.new()
    # Then override the plug... (advanced usage)
