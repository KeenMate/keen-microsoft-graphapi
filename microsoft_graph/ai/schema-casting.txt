SCHEMA CASTING AND VIEWS
========================

Modules: GraphApi.Schema.*, GraphApi.View


THE :as OPTION
--------------

All resource functions accept an :as option to cast JSON responses
into typed Elixir structs:

    # Single item
    {:ok, user} = GraphApi.Users.get("user-id", as: GraphApi.Schema.User)
    # => %GraphApi.Schema.User{id: "abc", display_name: "Alice", ...}

    # List (casts each item in "value")
    {:ok, %{"value" => users}} = GraphApi.Users.list(as: GraphApi.Schema.User)
    # => [%GraphApi.Schema.User{}, ...]

    # Combined with $select
    query = OData.new() |> OData.select(["id", "displayName", "mail"])
    {:ok, %{"value" => users}} = GraphApi.Users.list(query: query, as: GraphApi.Schema.User)
    # Fields not in $select will be nil in the struct


CASTING BEHAVIOR
----------------

- For collection responses (with "value" key): each item in the list is cast
- For single-item responses: the entire body is cast
- For :ok responses (204 No Content): no casting
- For errors: no casting

SCHEMA MODULE INTERFACE
-----------------------

Each schema module provides:

  defstruct [...fields...]     - Elixir struct with snake_case fields
  @type t                      - Type spec for the struct
  __field_mapping__/0          - Map of camelCase API names to snake_case atoms
  __field_names__/0            - List of camelCase API field names
  from_map/1                   - Converts camelCase map to struct
  to_map/1                     - Converts struct to camelCase map (nil fields omitted)

Example (GraphApi.Schema.User):

    user = GraphApi.Schema.User.from_map(%{
      "id" => "abc",
      "displayName" => "Alice",
      "mail" => "alice@contoso.com",
      "accountEnabled" => true
    })
    # => %GraphApi.Schema.User{
    #   id: "abc",
    #   display_name: "Alice",
    #   mail: "alice@contoso.com",
    #   account_enabled: true,
    #   ...
    # }

    GraphApi.Schema.User.to_map(user)
    # => %{"id" => "abc", "displayName" => "Alice", "mail" => "alice@contoso.com", "accountEnabled" => true}


NESTED CASTING
--------------

Schema modules recursively cast nested objects:

- password_profile => %GraphApi.Schema.PasswordProfile{}
- assigned_licenses => [%GraphApi.Schema.AssignedLicense{}]

Example:

    {:ok, user} = GraphApi.Users.get("user-id", as: GraphApi.Schema.User)
    user.password_profile
    # => %GraphApi.Schema.PasswordProfile{...} or nil

    user.assigned_licenses
    # => [%GraphApi.Schema.AssignedLicense{...}] or nil


FIELD MAPPING
-------------

Schema modules provide a __field_mapping__/0 function:

    GraphApi.Schema.User.__field_mapping__()
    # => %{
    #   "id" => :id,
    #   "displayName" => :display_name,
    #   "mail" => :mail,
    #   "userPrincipalName" => :user_principal_name,
    #   "accountEnabled" => :account_enabled,
    #   ...
    # }

This mapping is used by:
- from_map/1 for JSON -> struct conversion
- to_map/1 for struct -> JSON conversion
- OData.Filter for snake_case -> camelCase field resolution


VIEW MODULES
------------

Module: GraphApi.View

Views project a subset of fields from a schema module, providing:
- Smaller structs with only the fields you need
- Automatic $select injection (fetches only needed fields from API)
- Compile-time field validation against parent schema

Definition:

    defmodule MyApp.UserSummary do
      use GraphApi.View,
        schema: GraphApi.Schema.User,
        fields: [:id, :display_name, :mail, :job_title]
    end

Generated functions:
  defstruct           - With only the listed fields
  from_map/1          - Casts via parent schema, then takes only view fields
  to_map/1            - Converts back to camelCase via parent schema
  __select__/0        - Returns camelCase field names for $select
  __schema__/0        - Returns the parent schema module

Usage:

    # Automatically adds $select=id,displayName,mail,jobTitle
    {:ok, %{"value" => users}} = GraphApi.Users.list(as: MyApp.UserSummary)
    # => [%MyApp.UserSummary{id: "abc", display_name: "Alice", mail: "...", job_title: "..."}, ...]

The $select injection happens automatically when:
1. The :as module has a __select__/0 function
2. No explicit $select is already set in the query

If you provide your own $select in the OData query, the View's __select__
is NOT injected (your explicit select takes precedence).


VIEW COMPILE-TIME VALIDATION
-----------------------------

If you specify a field that does not exist on the parent schema,
a CompileError is raised:

    defmodule BadView do
      use GraphApi.View,
        schema: GraphApi.Schema.User,
        fields: [:id, :nonexistent_field]  # CompileError!
    end


USING SCHEMAS IN BATCH
-----------------------

Pass :as to _query variants for batch response casting:

    Batch.new()
    |> Batch.add("1", Users.list_query(as: GraphApi.Schema.User))
    |> Batch.add("2", Groups.get_query("id", as: GraphApi.Schema.Group))
    |> Batch.execute(client: client)

Each response body is individually cast by its schema.


GENERATING SCHEMAS
------------------

Schemas are auto-generated from Microsoft Graph metadata:

    mix graph.gen.schema

This reads the Graph API $metadata XML and generates Elixir modules
for both v1.0 and beta schemas.
